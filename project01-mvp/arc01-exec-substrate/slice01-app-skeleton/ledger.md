## What Worked

- **Compiling against the real toolchain instead of guessing LFE syntax from
  memory.** Several early drafts (the sup module's `init/1`, the `is-match`
  wildcard assumption) were wrong on the first pass; `rebar3 compile` /
  `rebar3 as test eunit` caught each one immediately and cheaply, well
  inside the iteration budget. Reading `lfe-rebar3/rebar3_lfe`'s own
  generated-template source (`priv/templates/*.tpl`) — ground truth from
  the plugin's own `rebar3 new` scaffolding — resolved the `project_plugins`
  + `provider_hooks` wiring and the `#M(...)` map-sigil question faster
  than iterating blind.
- **`rebar3 as test eunit`, not `rebar3 lfe ltest`, as the canonical test
  runner.** `ltest`'s `deftest` compiles straight to standard eunit
  `_test/0` functions; the built-in `eunit` provider gives correct
  process exit-code semantics (needed for K-6's tamper check and CI) where
  the plugin's own `lfe ltest` reporter does not set one on failure.
- **A `logger` handler at `level => error` writing to a public ets table**
  made "no error/crash reports during start/stop" a real assertion (K-3)
  instead of an eyeballed claim, with no new dependency.
- **Verifying `config/sys.config` by actually consulting and validating
  it** (not just eyeballing the term syntax) caught nothing this time, but
  is cheap insurance the same shape as compiling against the real
  toolchain.
- **The GitHub Actions outage during K-7** was handled by checking
  status.github.com rather than assuming a workflow defect, and by not
  grinding retries in a tight loop — each retry was spaced by `gh run
  watch`'s own natural wait, and the row's evidence documents the outage
  rather than hiding a flaky-looking history.
