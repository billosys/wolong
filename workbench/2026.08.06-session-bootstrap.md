## 3. Hard-won verifier protocols (your own failure modes — guard them)

Across five CDC passes, **every recurrent defect was in the verifying
apparatus, never the work under review**:

1. **Never capture exit codes through a pipe.** `cmd | tail; echo $?`
   reads the pipe's status. Five occurrences. Redirect to a file, test
   `$?` directly.
2. **Checksum every staged file against git before judging it.** The
   device-mount cache serves stale snapshots; one nearly became a false
   confabulation accusation against CC. Best channel: `git clone` the
   public repo in the sandbox and md5-compare against
   `device_bash: git show HEAD:<file>` — the clone is authoritative.
3. **Read the diff before trusting an extraction one-liner** (wrong
   README block index, regex overmatch — both happened; CC caught its
   own too).
4. **Never write a future operator decision as fact.** Prior session
   once drafted an arc gate as "ACCEPTED" before Duncan had seen it —
   caught pre-delivery. Gates are PENDING until the operator speaks;
   record acceptances only after they happen.
5. **Green + fail-loud = evidence.** Because every script in these
   projects fails loudly, a green run carries real information (that
   inference closed W-3 legitimately). It only works while nothing can
   fail silently — protect that property in review.
6. Gates must demonstrably be able to fail (tamper tests are ledger
   rows, not flourishes). An audit claim without an evidence pointer is
   not done. Evidence is perishable (GitHub log retention ~aged out
   mid-audit) — trigger fresh runs rather than lament.
